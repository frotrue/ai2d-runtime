# v0.3 implementation plan: bounded Event–Action games

## Objective

v0.3 tests whether a small set of typed, allocation-bounded operations can express complete grid games without a game-specific C++ escape hatch. The proof content is classic Snake plus Grid Collector. GameManifest and SceneSpec 0.2 remain accepted unchanged; the Breakout plan hash is pinned to `6721347758608948258`.

## Architecture boundary

The scenario compiler owns JSON parsing, strict schema and semantic validation, symbol resolution, numeric target resolution, ordered rule plans, and dependency inspection. The runtime owns fixed-tick dispatch and preallocated state. World remains a fixed-component container and bounded swept-AABB solver. Renderer, platform, and asset boundaries remain unchanged.

The new rule language is deliberately finite. It has lifecycle, logical-action, fixed-interval, and collision events; all-of typed conditions; and a closed action enum. It has no expression evaluator, user event emission, loop, recursion, tag query, arbitrary component access, scripting VM, or gameplay plug-in interface.

## Phases and validation

1. Preserve 0.2 and introduce 0.3 schema selection.
   - Validate with `python tools/engine.py validate samples/breakout/game.json --json`.
   - Inspect and pin the existing plan/source hashes.
2. Compile grids, systems, targets, rules, and numeric dispatch metadata.
   - Reject mixed manifest/scene versions, unknown fields and references, over-limit data, invalid targets, and unsafe ordering.
3. Execute grid motion, chain following, ordered rule actions, deterministic free-cell relocation, and extended snapshots.
   - Unit-test exact cell movement, reverse rejection, rule visibility/order, inactive follower reserves, retained re-entry, full grids, and steady-state allocation tracking.
4. Add fixed-tick logical input scripts and official packaging.
   - Test the extracted ZIP from a fresh temporary directory using hidden/offscreen frames.
5. Prove generality with declarative Snake and Grid Collector.
   - Both games must contain zero game-specific C++.
6. Run Debug, Release, ASan, GPU-off, Vulkan validation/synchronization validation, architecture, shader validation, benchmark, and packaging checks. Unavailable checks are reported as such.
7. Give only public documentation and schemas to an independent AI task. It must author and package a complete Snake without inspecting engine source or existing samples.
8. Submit the completed project bundle to ChatGPT Pro, wait for its full review, validate every finding locally, fix confirmed defects, and rerun affected checks.

## Capacity contract

- 64 logical grids per scene and 1,000,000 logical cells per grid.
- 512 rules per scene, 8 conditions per rule, 16 actions per rule.
- 32 occupancy groups per relocation action.
- All group ranges, dispatch tables, system state, snapshots, collision storage, and occupancy bytes are allocated during scene load/initialization.
- No project-owned heap allocation, capacity growth, per-tick string lookup, entity creation, or JSON parsing is permitted in measured steady state.

## Explicit exclusions

Scripting/VMs, recursive custom events, a general expression language, generic ECS/runtime components, animation, an editor, hot reload, save games, general rigid-body physics, pathfinding, AI, networking, and single-file content embedding are outside v0.3.

## Definition of Done

- Both 0.2 and 0.3 compile, run, inspect, and package; the 0.2 Breakout hash is unchanged.
- Snake implements path-following growth, food relocation, score, self/wall loss, full-board win, and restart declaratively.
- Grid Collector independently reuses grid and Event–Action primitives without chain following.
- Input scripts deterministically exercise both samples.
- Official Windows ZIPs contain a statically linked player plus only referenced content, deterministic entries, notices, and SHA-256 evidence.
- All available validation passes; unavailable items are not called PASS.
- The fresh-AI gate and the independently validated ChatGPT Pro review are recorded in the final report.
