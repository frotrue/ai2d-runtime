# v0.4 implementation plan — Bounded Entity Lifecycle & Object Pools

## Objective

v0.4 adds deterministic acquisition, return, expiration, reset, and reuse of objects whose slots already exist at scene load. It targets projectiles, enemies, pickups, effects, and traps without adding runtime entity creation or game-specific C++.

## Contract

- Add matching GameManifest/SceneSpec `0.4`; keep `0.2` and `0.3` unchanged.
- Require a bounded `pools` array in every 0.4 scene, including an empty array.
- Give each pooled spawn group exactly one lifecycle owner and one explicit exhaustion policy.
- Add ordered `spawn_from_pool`, `release_to_pool`, and `reset_pool` actions.
- Preserve ascending FIFO availability, acquisition order, authored initial active prefixes, exact tick lifetimes, interpolation history, retained snapshots, and deterministic hashes.
- Reserve all pool storage at scene load and keep measured execution allocation/capacity-growth free.
- Expose pool declarations/actions through inspect and lifecycle counters through run metrics.

## Delivery slices

1. Public plan types, stable diagnostics, schemas, parser, semantic validation, public-plan validation, inspect, and 0.4-only hashing.
2. Fixed pool FIFO/active-list/expiration storage, action execution, reset, snapshot, interpolation, checksum, and metrics.
3. Parser/runtime/churn/snapshot tests plus 0.2/0.3 hash regressions.
4. Projectile Arena (`recycle_oldest`) and Timed Pickups (`skip`) samples and deterministic input scripts.
5. ADR, GameSpec, migration, README, implementation report, build matrix, benchmark, and extracted Windows-package smoke tests.
6. A source-blind independent AI `pool_dodger` authoring/package gate.

## Explicit exclusions

Sprite animation, save/offline progression, tilemaps, particles, UI expansion, state machines, scripting/VM, runtime entity creation, and a dedicated spawn scheduler remain outside v0.4.
