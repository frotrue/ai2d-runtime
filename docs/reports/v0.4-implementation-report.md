# v0.4 implementation report

## Release identity

- Runtime version: `0.4.0`
- Schema: GameManifest/SceneSpec `0.4`
- Architecture decision: ADR-0011
- Compatibility: GameSpec 0.2 and 0.3 remain accepted without hash changes

## Delivered behavior

v0.4 implements fixed-capacity object pools over scene-load-created entities. Numeric pool indices, FIFO slot arrays, intrusive active-order links, expiration ticks, dispatch metadata, and snapshot buffers are established before gameplay. The runtime performs no entity creation or container growth while acquiring, releasing, recycling, resetting, or scanning lifetimes.

The compiler and public `GamePlan` validator enforce pool ownership, event context, target identity, component requirements, finite derived positions, lifetime bounds, and collision endpoint exclusivity. Inspect exposes compiled pool metadata; run JSON exposes all lifecycle counters. `GAME_POOL_INVALID` separates authoring errors from `RUNTIME_POOL_STATE_INVALID` invariant failures.

## Declarative samples

- `samples/projectile_arena`: input spawning, target-position copy, velocity/lifetime overrides, collision release, score/restart, and a three-slot `recycle_oldest` pool.
- `samples/timed_pickups`: fixed-interval authored-position spawning, collection release, automatic expiration, retained scene state, and a two-slot `skip` pool.
- `samples/pool_dodger`: source-blind release-gate game with fixed-interval hazards and pickups, collision return, automatic lifetime expiry, score/health, game over, and restart. Its two-slot hazard pool uses `recycle_oldest`; its one-slot pickup pool uses `skip`.

All three samples contain zero game-specific C++ and use project-owned procedural sprites/font assets. `pool_dodger` was authored by an independent AI session that did not inspect engine source, tests, or pre-existing samples.

## Test coverage

Automated tests cover parser and public-plan rejection, mixed versions, ownership conflicts, component and endpoint constraints, FIFO behavior, exhausted skip/oldest recycle, release miss, ordered same-tick actions, exact lifetime boundaries, reset, retained snapshots, 10,000-slot initialization, sustained churn, and tracked zero-allocation execution. Existing Breakout, Snake, and Grid Collector regression suites remain enabled.

## Known boundary

Pools require a capacity chosen at authoring time. Lifetime scanning is linear in currently acquired pooled slots. The runtime still intentionally lacks dynamic entity creation, arbitrary scripting, animation, persistence, tilemaps, particles, and a general-purpose editor.
