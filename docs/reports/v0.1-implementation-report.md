# v0.1 implementation report

- Status: complete on the reference host
- Evidence date: 2026-08-12 (Asia/Seoul)
- Project: `game_runtime_dev` (`ai2d` CMake target prefix)

## 1. Executive summary

v0.1 is a working C++23 + SDL3 + Vulkan 1.3 vertical slice, not an engine design proposal. It accepts a small versioned JSON ScenarioSpec, rejects invalid authoring with stable diagnostics, resolves names and dependencies into a deterministic numeric `ExecutionPlan`, executes fixed dense world operations, extracts and culls sprites, and submits textured instances through a private Vulkan/VMA backend. The same command spine builds, validates, runs, inspects, profiles, benchmarks, fingerprints, compares, and explicitly promotes local baselines.

The five hypotheses are supported within the stated host and workload boundary:

- H1: static, moving, and four-texture workloads are expressed entirely as ScenarioSpec fixtures; no scenario-specific gameplay C++ was added.
- H2: the dense world, extraction, culling, batching, upload, CPU submission, and GPU pass are measured separately through 100K entities. The visible 100K path identifies queue construction as the dominant CPU phase; the mostly-invisible path shows the expected shift toward extraction.
- H3: all 32 final benchmark results report zero tracked project C++ heap allocations and zero capacity-growth events in their measured intervals. Frame-arena overflow is zero only where the suite instruments an arena; otherwise it is explicitly unavailable rather than fabricated as zero.
- H4: invalid specs, stale entities, texture handles, upload capacity, device capability, Vulkan callback messages, and benchmark failures have structured diagnostic paths. Eight invalid fixtures pin eight semantic/compiler codes.
- H5: same-fingerprint comparison, robust dispersion, absolute floors, explicit incomparability, immutable promotion, noise warnings, and immediate invariant failure are implemented and tested. The final comparison is WARN rather than FAIL, with all warning reasons retained.

The v0.1 Definition of Done is satisfied. All implemented checks pass. UBSan is unavailable with MSVC and is recorded as unavailable rather than passed. The limits below prevent extending this result into cross-platform, general-engine, full-memory, or absolute-frame-rate claims.

## 3. Architecture decisions

All eight ADRs remain accepted; measured evidence did not trigger a replacement ADR.

| ADR | Decision | Implemented consequence |
|---|---|---|
| ADR-0001 | Bind v0.1 to five hypotheses and explicit anti-goals | Three components, two operations, three authoring fixtures, one sprite pipeline, and sequential execution only |
| ADR-0002 | Vulkan 1.3 renderer-specific backend | Dynamic rendering and synchronization2; no RHI, render graph, or device-loss state machine |
| ADR-0003 | Raw Vulkan C API with small move-only ownership | Explicit backend-local lifetimes, VMA isolated to one implementation translation unit, no Vulkan-Hpp dual path |
| ADR-0004 | Fixed dense world | `{index,generation}` entities, swap-remove dense stores, sparse lookup, smaller-store query iteration, reserve-before-run |
| ADR-0005 | Load-time ScenarioSpec to numeric sequential plan | JSON and strings stay outside the frame loop; canonical descriptors own access/query/cost/allocation metadata |
| ADR-0006 | Fingerprinted offscreen benchmark policy | Distribution statistics, MAD/noise floors, explicit promotion, no cross-machine or absolute-FPS gate |
| ADR-0007 | Ascending layer and texture batching within a layer | Deterministic batch count; strict same-layer alpha order intentionally not promised |
| ADR-0008 | Persistently mapped per-frame instance regions | Two fixed-capacity VMA-backed regions, no measured growth, explicit capacity failure |

The architecture checker is a secondary guard over CMake visibility. It prohibits SDL/Vulkan/parser leakage, forbidden dependency edges, and direct allocation primitives in project hot-path directories. Its final run scanned 54 source/header files and found zero violations.

The only material environment-driven plan adjustment was bootstrapping checksum-pinned, copy-only Vulkan SDK and Slang distributions because validation layers, `slangc`, and `spirv-val` were absent initially. No GLSL fallback was introduced. The GPU driver still supplies the runtime Vulkan implementation.

### Independent GPT Pro review and remediation

On 2026-08-12 the complete 99-file source bundle was independently reviewed with ChatGPT Pro using GPT-5.6 Sol at Pro 5/5. The review completed before any finding was accepted. Each finding was then reproduced against the local source; all ten were confirmed and fixed, with regression coverage added before the cross-preset replay above.

| Finding | Severity | Confirmed remediation |
|---|---|---|
| Mutable `ExecutionPlan` bypassed compiler validation | High | Full public-plan validator at compile and runtime boundaries; invalid enum/index/count/hash/cardinality plans rejected before mutation |
| World/storage re-reserve corrupted sparse state | High | Reserve is fallible and rejected after population or during a borrowed query |
| Finite arithmetic overflowed and wrapping could loop indefinitely | High | Checked double intermediates, stable numeric diagnostic, constant-time `fmod` wrapping |
| OUT_OF_DATE acquire after fence reset could poison a frame | High | Acquire now precedes fence reset; deterministic recovery and terminal submit-failure tests |
| Vulkan initialize/resize was non-transactional | Medium | Rollback on partial initialize; temporary replacement resources; terminal shutdown when recovery is unsafe |
| Transform scale and sprite pivot were ignored | Medium | Scale applied during extraction; pivot carried through culling, instance data, shader, and pixel smoke |
| Benchmark artifacts and baseline promotion trusted editable fields | Medium | Strict document/result/distribution validation, fingerprint rehash, recomputed eligibility, adversarial tests |
| Typed frame-arena byte multiplication could overflow | Medium | Pre-multiplication bounds check and overflow accounting |
| CLI JSON errors and profile JSONL writes were inconsistent/destructive | Medium | Stable JSON failure envelopes and checked same-directory temporary write plus atomic replacement |
| GPU-disabled configuration failed link/contract coverage | Medium | Renderer-independent queue target, structured stubs, dedicated `gpu-off` preset and 37-test gate |

The remediation replay also exposed two integration issues that were not separate GPT Pro findings: the synthetic scenario benchmark needed to compute the canonical plan hash, and its Debug-only failure accumulator had to be constructed outside the measured allocation scope. Both are now regression-covered. A fresh full quick sweep across 1K/10K/50K/100K produced 32/32 passing results, passed strict artifact validation, reported zero tracked C++ allocations and capacity growth, and represented all uninstrumented arena values as explicit unavailable data.

## 7. Known limitations

- Verification is from one Windows/MSVC/RTX 3060 host. Linux, macOS, other GPU vendors, and lower-end Vulkan 1.3 devices are unverified.
- MSVC ASan passed, but UBSan is unavailable. This leaves undefined-behavior coverage weaker than on a compiler that supports both.
- Physical core count and process RSS are `null` with explicit unavailable reasons. VMA occupancy and project allocation tracking do not capture all external, driver, loader, SDL, or OS allocation behavior.
- The complete evidence run uses the documented quick sampling mode. p95/p99 are observations, p99 is not a gate, and no result is an absolute FPS promise.
- Performance measurements use a fixed 640×360 offscreen target to exclude WSI/vsync. Presentation is correctness/resize smoke evidence, not a presentation-performance benchmark.
- The repository has no commit yet and all project files are untracked, so artifacts identify a dirty source state instead of an immutable revision. The named baseline is local and ignored, not a published cross-machine baseline.
- Scenario expressiveness is intentionally limited to three components, procedural RGBA textures, deterministic spawn patterns, and two sequential operations. There is no custom operation escape hatch, decoder, hot reload, persistent plan, or generic asset system.
- Execution and rendering are single-threaded. Dense scans and comparison sorting are intentionally simple; no job system or spatial index exists.
- Sorting is deterministic by layer, texture handle, and source order, but strict alpha ordering among different textures in one layer is not guaranteed. Authors must use separate layers where overlap order is semantically required.
- Device-loss recovery is not implemented. Unsupported capability and ordinary resource errors are structured, but a lost Vulkan device is outside v0.1.

## 8. Deferred items

These are deliberate scope exclusions, not hidden incomplete work:

- Generic/archetype ECS, runtime component registration/reflection, plugins/ABI, scripting/VM/expressions, full Game IR, code generation, optimization, and automatic scheduling.
- Threads/jobs/work stealing, spatial structures, collision/physics, animation, tilemaps, particles, audio, UI/ImGui, and an editor.
- Runtime decoding/hot reload, a generic asset pipeline or atlas compiler, bindless/descriptor-indexing, compute/GPU-driven culling, indirect draws, generic RHI/render graph/materials/post effects/lighting.
- Networking, 3D, mobile/console/web targets, automatic device-loss recovery, and speculative factories/registries/interfaces.

A deferred feature should enter only after a workload or measured failure supplies a concrete contract. The mostly-invisible 100K result is useful evidence about extraction cost, but its 1.5625 ms median does not justify adding a spatial index before the larger visible-path queue cost is addressed.

## 9. Next experiment

Run one bounded render-queue experiment: preserve the current ordering contract while comparing the existing comparison sort with a no-sort uniform-batch fast path, optionally followed by a packed-key linear/radix grouping variant for the four-texture case. The evidence is direct: at 100K visible sprites, queue formation consumes 3.88–4.21 ms and is the largest CPU phase, while upload is about 0.33 ms in the raw path and the GPU pass is about 0.93 ms. The single-layer/single-texture cases are already known at extraction time to have one batch, yet they still pay the general sort.

The experiment should reuse the same five integrated workloads and fingerprint policy, retain deterministic layer/texture/source-order output, and require unchanged pixel/cardinality/batch/allocation/validation tests. Adopt a specialized path only if repeated full-duration measurements reduce queue median without increasing noise or breaking the four-texture and ordering contracts. This is a focused change to the existing renderer; it does not require an ECS, job system, spatial tree, RHI, or full IR.
