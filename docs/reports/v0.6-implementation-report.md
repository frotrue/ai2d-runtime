# v0.6 implementation report

## Release identity

- Runtime version: `0.6.0`
- Schema: GameManifest/SceneSpec `0.6`; prefab/localization/game-test/font metadata `1`
- Architecture decision: ADR-0013
- Compatibility: GameSpec 0.2-0.5 remain accepted without behavior or hash changes

## Delivered behavior

v0.6 delivers five concrete, bounded foundations rather than a general extension layer:

- fixed-tick `once`, `loop`, and `ping_pong` sprite clips with typed completion events;
- external non-recursive prefab files expanded into concrete components by the compiler;
- exact-plan, checksum-protected, bounded and transactional save slots for persistent scenes;
- logical-grid-backed rendered tile arrays and clamped integer fields with typed cell reads/writes;
- SDL gamepad input profiles, deterministic fixed/follow cameras, compile-time anchored/stacked localized UI, one streamed WAV music ring, and preallocated deterministic sprite particles.

All authored names used by simulation compile to numeric indices. Every new hot-path collection is sized before play. Save and music file I/O remains outside `fixed_tick` and is processed at the exact completed-tick boundary. The compiler rejects more than 4,000,000 aggregate tile/field cells, more than 100,000 aggregate particle slots, or an exact worst-case save image larger than 64 MiB. No scripting, reflection, generic ECS, runtime entity factory, recursive prefab, dynamic UI tree, or general asset pipeline was introduced.

## Declarative sample

`samples/content_foundations` combines all five slices with zero game-specific C++:

- an externally defined animated actor and a one-shot animation completion rule;
- rendered tiles and an integer energy field mutated by ordered actions;
- particle emission and deterministic camera shake/follow;
- keyboard and gamepad profiles;
- anchored horizontal localized UI with two locales;
- exact-plan persistent save/load/delete actions;
- a project-generated PCM WAV music stream.

The normal and save-round-trip `game-test-v1` scripts pass twice from fresh runtimes. `game verify` creates an isolated temporary save root for every invocation and repeat, so user saves and earlier repeats cannot affect observations. Procedural assets are generated only by `tools/generate_sample_assets.py`.

## Independent GPT Pro review

The completed [GPT Pro review](https://chatgpt.com/c/6a7da862-8084-83ea-bbe3-fa1a3229cb0d) judged the five features a strong architectural fit: they remain closed declarative specializations with numeric plans, compile/load-time bounds, fixed-tick determinism, preallocated hot paths, structured diagnostics, and no generic gameplay escape hatch. It found ten actionable implementation defects. Every finding was reproduced or confirmed against the live workspace before changing code, and all ten were fixed:

| ID | Severity | Confirmed defect | Remediation |
|---|---|---|---|
| F-001 | High | Absolute dependency paths leaked into the 0.6 plan/save identity. | Hash normalized content-root-relative dependency names; relocation regression proves identical identity. Legacy hash branches remain untouched. |
| F-002 | Medium | Pressing a second physical binding retriggered an already-held logical action. | Derive edges from aggregate state transitions while preserving a complete between-polls tap. |
| F-003 | Medium | A profile change during a multi-tick batch left later ticks on stale bindings. | Re-resolve held physical state at the next fixed-tick boundary; batched and one-tick runs now match. |
| F-004 | Medium | Concurrent save writers shared one `.tmp` filename. | Give every writer a unique sibling temporary name and retain atomic replacement/retry behavior. |
| F-005 | Medium | Fresh scene entry did not apply an authored clip's frame-zero UV. | Apply initial animation texture/UV during scene construction and cover the pre-first-tick checksum. |
| F-006 | Medium | Checksum-valid saves could bypass bounded counter and derived-state invariants. | Revalidate ticks, rule/particle/camera counters, particle order structures, and arithmetic headroom before transactional commit. |
| F-007 | High | Preference names and dependency paths admitted traversal/device-name or parser/public-validator inconsistencies. | Share strict safe-component validation and require canonical regular content files without symlink/reparse indirection at both boundaries. |
| F-008 | Medium | Anchors/stacks mixed top-left and center coordinates. | Compile and revalidate all element and stack positions as centers with complete rectangle bounds. |
| F-009 | Low | The schema allowed four axis bindings although the numeric plan stores two. | Set schema and parser/public-plan limits to two and reject zero deadzones consistently. |
| F-010 | Medium | Particle slot selection scanned capacity for every emission. | Replace scans with a reserved minimum heap plus intrusive active queue and expose bounded slot-operation metrics. |

After remediation, the complete matrix and package evidence above were rerun from the modified tree. The independent review gate is therefore closed rather than merely advisory.
