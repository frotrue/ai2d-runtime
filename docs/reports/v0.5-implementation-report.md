# v0.5 implementation report

## Release identity

- Runtime version: `0.5.0`
- Schema: GameManifest/SceneSpec `0.5`; game-test `1`; font metadata `1`
- Architecture decision: ADR-0012
- Compatibility: GameSpec 0.2–0.4 remain accepted without behavior or hash changes

## Delivered behavior

v0.5 implements fixed-capacity motion-segment capture and deterministic trigger contacts for static, kinematic, and dynamic AABB bodies. It separates observational triggers from bounded solid reflection, adds explicit kinematic linear motion, preserves contact lifecycle in retained snapshots, invalidates contacts on object lifecycle changes, and exposes captured contact positions to ordered actions.

The public test compiler resolves input, state, scene, group, entity, and metric names before execution. `game verify` evaluates 0-based tick assertions, creates a fresh runtime for each repetition, and compares state plus contact checksums and cumulative observations. Trigger processing, contact diffing, event dispatch, pool reuse, and numeric observations do not add a scripting or gameplay-C++ escape hatch.

## Declarative samples

- `samples/pool_siege`: moving bullet, enemy, and item pools; direct trigger endpoints; captured-position item spawning; skip/recycle policies; score, health, win/loss, and restart.
- `samples/contact_course`: two independently moving kinematic bodies; one persistent begin and one separation end; no shooter-specific proxy or follower.

Both samples contain zero game-specific C++ and use project-owned procedural sprite/font assets.

## Test coverage

Automated coverage includes every trigger body pairing, high-speed pass-through, contact positions, reflected dynamic segments, begin persistence, end diffing, one-tick pass-through, lifecycle invalidation, stale multi-event suppression, retained/reset snapshots, direct pooled endpoint release, linear-motion ownership/order checks, malformed capacities/state, verify assertions/repeats, and 10,000-entity sparse-contact churn with tracked allocation/capacity checks. All six 0.2–0.4 source/plan hash pairs are pinned.

## Known boundary

Solid response remains one dynamic endpoint against static/kinematic. Contact storage is author-bounded, AABBs do not rotate for collision, and the runtime still intentionally lacks general rigid-body physics, scripting, runtime entity creation, and image-golden verification.
