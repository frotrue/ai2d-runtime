# v0.5 implementation plan — Bounded Motion & Trigger Contacts

## Objective

v0.5 adds deterministic direct contact events between moving bounded objects and a black-box verification contract. It deliberately does not become a general physics engine.

## Contract

- Add matching GameManifest/SceneSpec `0.5`; keep `0.2`–`0.4` behavior and hashes unchanged.
- Require every 0.5 collision rule to declare `solid` or `trigger` interaction.
- Record bounded motion segments and produce ordered `contact_begin`/`contact_end` events for every body combination.
- Add `linear_motion` for explicitly authored kinematic integration without double ownership.
- Capture contact-time positions and make them available to collision endpoint targets.
- Keep active contact pairs, event buffers, snapshots, and metrics fixed-capacity and deterministic.
- Add `game-test-v1` plus `game verify` with numeric observations and repeat comparison.
- Expose interaction, event phase, capacity, and motion ownership through inspect.

## Delivery slices

1. Public types, diagnostics, 0.5 schemas, parser, public-plan validation, inspect, and 0.5-only hashing.
2. Motion-segment capture, relative trigger sweep, sorted contact lifecycle, snapshots, invalidation, ordering, and metrics.
3. Kinematic `linear_motion`, ownership/order validation, pool endpoint integration, and captured-position actions.
4. Game-test compiler, numeric observation API, CLI/wrapper `verify`, assertion diagnostics, and repeat determinism.
5. Pool Siege and Contact Course samples with fixed-tick verification scripts and procedural assets.
6. Parser/runtime/collision/churn regression tests, build matrix, benchmark, Windows packages, extracted smoke, and source-blind independent AI gate.
7. ADR, GameSpec, migration guide, font metadata schema, README, and implementation report.

## Explicit exclusions

Dynamic-dynamic solid resolution, mass, force, friction, rotating collision shapes, joints, generic rigid-body physics, frame capture/golden-image comparison, expressions, scripting/VM, callbacks, runtime entity creation, and a generic ECS remain outside v0.5.
